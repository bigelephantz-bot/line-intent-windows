# LINE 意圖助手（Windows）

Windows 桌面工具：擷取自己選取的 LINE 視窗、框選聊天區域、本機 OCR，再將確認過的文字交給 **JEV 判斷模型**。顯示對方的可能意圖、需求、建議動作與互動緊張度。介面使用繁體中文。

這是參考 [Jev Chat Assistant](https://github.com/jev-chat/jev-chat-jarvis) 與 [Windows 姊妹專案](https://github.com/jev-chat/jev-chat-windows) 的獨立 C# 改寫，並非 LINE 或原作者的官方產品。原專案 Windows 版本針對微信，本工具將擷取流程改成 LINE 專用視窗選擇與手動區域框選。

## 開始使用

1. 開啟 `dist\LineIntent-win-x64-0.7.0\LineIntent.exe`，或專案根目錄的 `Start-LineIntent.cmd`。發布版已包含 .NET 執行環境，無需安裝 Python；舊版發布資料夾保留。
2. 點「API 與設定」，填入 OpenRouter／TypeSafe API Key，選擇 JEV 服務；JEV 模型留空即可。若需要回覆草稿，可啟用 LLM、填入 OpenRouter LLM 模型 ID；LLM Key 留空沿用 OpenRouter Key，也可另填。
3. 在 Windows LINE 開啟目標對話，回到工具按「重新整理」→ 選擇視窗 →「擷取 LINE」，框選完整訊息區，保留左右氣泡與邊界，避開標題／聯絡人清單／輸入框。也可直接複製 LINE 對話後使用「貼上文字」。
4. OCR 會依氣泡位置標示左側「對方」、右側「我」，並依畫面上下順序排列。點選一列可放大原圖，點文字格即可補字；無關項目勾選最右側「略過」。底部明確列出還需處理的列號，改說話者不會補上空白文字。貼上文字則先確認自己的完整姓名，支援含空格姓名及「時間 姓名 訊息」格式。
5. 按「分析對方意圖」，在中間的「理解可能意圖」欄查看需求與建議動作；啟用 LLM 時，最多三條草稿會顯示在右側獨立的「回覆草稿」欄，可逐則複製。分析成功後可按「只重新產生草稿」，只呼叫一次 LLM、保留意圖分析；對話或設定變更會清除暫存，必須重新分析。

可先使用這段例子（「載入範例」會填入相同內容；按「分析」才會呼叫服務）：

```text
我：今天有空聊一下嗎？
對方：今天真的很累，明天再說好嗎
```

未標示說話者的行僅作未知來源背景，不會自動當作對方。最後一則是自己回覆也可以分析：工具定位最近一則對方訊息，後續自己的回覆仍作背景，並顯示提醒。群聊請先整理成特定一位對象與你的對話；未知的第三位發話者會讓匯入停止，不會默默丟棄。

LINE 複製格式的虛構範例：

```text
07:42 Alex Chen 陳小明 今天改去美術館
07:44 王小華 我先查開放時間
07:45 Alex Chen 陳小明 好，我查交通
```

第一次解析必須明確選自己的姓名，不會將第一位發言者猜成自己。0.5.0 可點姓名欄的文字區或左側標籤展開選單，不必對準箭頭。姓名建議來自文字前綴；候選不完整時勾選「手動輸入姓名」，關閉手動模式也會保留自訂值。亦支援 Tab 分隔及同一訊息的多行文字；辨認出的日期標頭／時間會在轉換時移除，預覽中可檢查結果。

0.4.0 起，帶時間的完整「姓名已收回訊息」系統通知會自動略過（支援已確認姓名、有無空格、Tab、尾端空白及不帶姓名的通知），不送入意圖分析。匯入預覽與主畫面會提示略過筆數。一般句子如「我看到已收回訊息」不會被刪除；未知第三人的通知仍須確認，不會默默忽略。若整段只剩收回通知，會顯示略過筆數並提示缺少對方對話。

0.7.0 已修正審查確認的兩項 P2：收回通知不再參與一般訊息的姓名共同前綴推測；日期位於訊息內時保留為正文並提醒，只有訊息外的起始日期標頭略過。純文字無法確定日期是否為分隔線時，優先保留，供你在預覽後修正。姓名推測仍只是候選，資料不足時請手動填完整姓名。

本版也移除擷取／OCR 的 PNG 中間轉碼，直接複製像素；氣泡遮罩緩衝區重用後會清空。合成 4K 測試的暖身後託管配置由約 64 MiB 降至 0.02 MiB，這不是整個程式的記憶體占用。詳細數據見 [驗證記錄](docs/verification.md)。

## OCR 說話者辨識

0.3.0 保留文字座標，偵測常見灰色／綠色聊天氣泡，以氣泡位置組合成訊息。多行氣泡會合併，同時顯示左右對話的圖片會由上往下排序，避免先讀完整左欄再讀右欄。文字座標會套用 Windows OCR 的旋轉角度及圖片 DPI 校正。

氣泡外的已讀、時間、日期標記會依精確格式排除；同樣文字若在氣泡內，仍保留為對話。漏讀的小氣泡會嘗試局部放大 OCR，仍失敗則保留空白列供補正，不會默默刪掉訊息。上下邊緣被截斷時會提醒。

0.6.0 加入孤立單字重試：先裁出字形，以原色與二值化方式進行本機辨識，並使用不會輸出的定位文字協助 OCR 找到文字行；只取回原字所在範圍的結果。兩種結果相衝突時仍保留空白，不以預設詞猜填。這改善了已提供樣本中的「嗯／唉」，但不保證所有字型、裁切及貼圖都能辨識。

核對表中的「略過」是獨立勾選欄；勾選後該列不要求文字或說話者。尚有其他空白或未確認列時，套用會直接定位到該列，底部顯示列號，不再反覆彈出同一句錯誤。也可使用「填入『嗯』」「填入『唉』」手動補正選取列，或按「補字／修改」輸入其他文字。

請保留整個聊天區的左右邊界，避免只框選文字本身。任意背景圖、自訂配色、貼圖、照片及群聊不保證自動判定正確，模糊項目應核對或略過。OCR 可能有錯字；角色與文字在套用前都可修改，這一步不呼叫模型。

## 需求與擷取範圍

- Windows 10 2004（19041）以上／Windows 11，x64。使用一般使用者權限執行。
- Windows 桌面 LINE 的 `LINE.exe` 可見視窗。瀏覽器版／瀏覽器擴充版不列入擷取目標。
- 優先使用 Windows Graphics Capture 直接取得指定 LINE 視窗，不會因顯示器工具的透明覆蓋視窗或工作列而失敗；最小化時先還原。取得整個 LINE 視窗後，先框選聊天區域才進行 OCR。Windows 可能短暫顯示擷取邊框。
- Windows OCR 語言資源；工具設定會列出已安裝語言。若缺少中文，至「Windows 設定 → 時間與語言 → 語言與地區」安裝對應語言的 OCR 功能，也可直接貼上文字。
- 有額度及模型使用權限的 OpenRouter 或 TypeSafe Key；分析需要網路。Key 的服務商必須與選擇的服務一致。

## JEV 設定

| 服務 | 固定端點 | 留空時使用的模型 |
| --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api/alpha/decisions` | `typesafe/jev-1.13` |
| TypeSafe | `https://api.typesafe.ai/v1/systemone` | `jev-latest` |

JEV 使用 `state + questions → answers` 判斷協定，**不是**一般 Chat Completions。每次 JEV 分析只有一次請求、七道判斷題，不自動重試。無法連線或格式缺失會顯示錯誤，不會用假的中性結果代替。服務商可能更新模型，設定可自行輸入模型 ID。切換服務會重設 JEV 模型。

LLM 是獨立的選用步驟，預設關閉。啟用後，JEV 成功時會將相同對話、關係背景與判斷結果送到 `https://openrouter.ai/api/v1/chat/completions` 生成草稿。LLM 模型 ID 由你填入，例如你帳戶可使用的 `供應商/模型名稱`；不內建容易過期的預設模型。LLM 失敗時保留已完成的 JEV 判斷。TypeSafe Key 不會被拿去呼叫 OpenRouter。

「有足夠資訊可具體回應」衡量目前上下文是否支持具體內容，並非建議何時傳送。模型信心、選項機率均不代表現實中的正確率；工具無法知道別人的真實內心。相關協定與來源見 [docs/jev-protocol.md](docs/jev-protocol.md)。

## 資料處理

截圖及聊天文字只保留在記憶體。只有按下「分析」才會傳送文字框中的對話與你設定的關係背景到所選 JEV API；啟用 LLM 時另傳至 OpenRouter 產生草稿。圖片不會上傳。不讀取 LINE 資料庫或程序記憶體，也不修改 LINE。關閉工具或按「清除」即可清除介面中的對話與結果；應用程式不儲存聊天記錄或內容日誌。手動複製草稿後會留在 Windows 剪貼簿，是否同步由你的 Windows 剪貼簿設定決定。

API Key 以 Windows DPAPI 使用者範圍加密後保存，其他設定以 JSON 保存於：

```text
%LOCALAPPDATA%\LineIntent\settings.json
```

同一 Windows 使用者下的其他程式仍可能解密 DPAPI 資料，因此這不提供對已受入侵帳戶的防護。關閉 LLM 開關、清空三個 Key 欄位並儲存即可移除保存的密鑰。API 服務商對收到文字的保存方式由其政策決定。開源前的 Git 防護與提交檢查請見 [SECURITY.md](SECURITY.md)。

本版支援手動意圖分析與選用 LLM 草稿；不在背景持續擷取或自動發送。`--self-test` 例外會將**內建合成文字**的介面預覽及診斷結果寫到指定目錄，不會擷取真實聊天或呼叫 API。

## 從原始碼執行

安裝 .NET 10 SDK，開啟 PowerShell：

```powershell
dotnet run --project src/LineIntent/LineIntent.csproj -c Release
```

建置自含執行環境的 x64 發布資料夾與 ZIP：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

測試判斷協定／錯誤處理，以及本機 OCR／加密／介面：

```powershell
dotnet run --project tests/LineIntent.Tests -c Release
dotnet build src/LineIntent/LineIntent.csproj -c Release
& .\src\LineIntent\bin\Release\net10.0-windows10.0.19041.0\LineIntent.exe --self-test .\artifacts\smoke | Out-Null
Get-Content .\artifacts\smoke\results.txt
```

測試使用假的 HTTP 回覆及合成聊天文字；不使用或讀取你的密鑰。`docs/verification.md` 記錄這次實際驗證結果與仍需人工驗證的部分。

另有可手動觸發的專用 Windows UI CI，會先檢查繁中 OCR、字型與未鎖定的桌面，失敗不略過測試。工作流程已加入，但正式在 GitHub 執行仍須連接專用測試機，見 [Windows UI CI 說明](docs/windows-ui-ci.md)。

## 常見問題

| 現象 | 處理方式 |
| --- | --- |
| 找不到 LINE | 開啟 Windows 桌面 LINE 的聊天視窗，按重新整理；也可貼上文字。 |
| 擷取失败 | 查看完整錯誤對話框及階段代碼。僅 Windows 不支援指定視窗擷取時，才回退為要求完整可見的螢幕擷取。 |
| OCR 有錯字、空白或未確認列 | 點文字格補字；無關項目勾選右側「略過」。查看底部待處理列號，其他未確認列仍須完成。 |
| HTTP 401／402／403 | 確認 Key 與服務商相符、帳戶額度及模型權限。 |
| 模型或網路錯誤 | 確認模型 ID 與網路後手動重試；逾時上限 35 秒，取消不能撤回已送達服務商的請求。 |
