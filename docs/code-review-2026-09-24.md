# 程式碼審查與優化建議 — 2026-09-24

**0.7.0 更新：以下兩項 P2 已修正並加入回歸測試；草稿單獨重生、OCR 像素傳遞／緩衝區優化、受控 Windows UI CI 工作流程也已實作。** 下文保留當時問題與量測紀錄。最新結果見 [驗證記錄](verification.md)，CI 接線條件見 [Windows UI CI](windows-ui-ci.md)。

本次完成姓名選單的整列點擊修改。審查發現 **2 項可重現的 P2 功能問題**，以下列為待修正；沒有改動匯入或判斷核心的語意。建議先處理資料正確性，再優化草稿重試及 OCR 記憶體。

## 審查發現

### P2 — 收回通知可能截短含空格的候選姓名

位置：[LineClipboardImporter.cs](../src/LineIntent.Core/LineClipboardImporter.cs)，`SuggestNames()` 第 47–63 行，尤其第 57 行。

候選姓名以同一個首字串的最長共同前綴推測，但包含系統通知。一般訊息是 `Alex Chen 陳小明 北門見`，收回通知是 `Alex Chen 陳小明已收回訊息`；第三個詞不同，使推測結果從完整姓名縮成 `Alex Chen`。

合成案例已重現：候選清單不包含 `Alex Chen 陳小明`；直接選縮短候選後，轉換回報略過通知 **0 筆**，並把通知放入訊息正文。這會讓前版「略過收回通知」在特定姓名格式下失效。

**建議修正：** 姓名推測與通知解析分開處理，排除已辨識的通知列對共同前綴的影響；不能明確判斷時要求輸入完整姓名，不要把不確定前綴當成已確認身分。保留普通訊息提及「已收回訊息」的文字。新增「候選姓名 → 選取 → 轉換 → 略過數量」整條流程測試，不能只測已提供正確姓名的 `Convert()`。

目前可用的處理方式：勾選「手動輸入姓名」，輸入完整 LINE 顯示名稱。

### P2 — 多行正文中的純日期會被當成日期標頭移除

位置：[LineClipboardImporter.cs](../src/LineIntent.Core/LineClipboardImporter.cs)，`Convert()` 第 97–102 行。

程式在判斷文字是不是上一則訊息的延續前，先無條件執行 `IsDateHeading()`。例如：

```text
08:00 王小華 下次活動日期
2026/10/01
08:01 Alex Chen 陳小明 好
```

實測轉換結果移除了日期，只留下「下次活動日期」。雖然有一般性的「已略過日期標頭」提醒，但這個日期本來是正文，分析會失去活動時間。

**建議修正：** 日期格式不應單獨決定其為系統標頭。結合訊息邊界判斷；無法區分時保留原文，或讓使用者在預覽中指定「日期標頭／訊息續行」。新增正文日期、真正日期分隔線以及日期後還有續行的測試。

## 效能實測

使用 [ReviewBenchmarks](../tools/ReviewBenchmarks/Program.cs) 的合成資料，無私人圖片、剪貼簿、API Key 或模型請求。Windows x64，.NET SDK 10.0.401、執行環境 10.0.12，16 個邏輯處理器。各案例先暖身一次，再測量 5 次。

| 工作 | 中位時間 | 最大時間 | 每次託管記憶體配置中位數 |
| --- | ---: | ---: | ---: |
| 30 則訊息，709 字元 | 0.09 ms | 0.10 ms | 0.04 MiB |
| 500 則訊息，12,389 字元 | 0.74 ms | 0.75 ms | 0.68 MiB |
| 1920×1080 氣泡偵測 | 16.26 ms | 22.36 ms | 26.22 MiB |
| 3840×2160 氣泡偵測 | 50.77 ms | 53.12 ms | 64.18 MiB |

這些是本機微型測量，不是整條擷取／OCR／網路的延遲；記憶體數字是配置量，不是常駐或尖峰用量，也未包含 GDI／GPU 的原生記憶體。時間會隨硬體、JIT、背景負載與畫面內容改變。原始結果在本機忽略目錄 `artifacts/review-2026-09-24.json`。

## 優化順序

| 優先 | 建議 | 原因與驗收方式 |
| --- | --- | --- |
| 1 | 先修上面兩項匯入問題 | 它們會改變模型收到的內容；修正後應保留完整姓名與正文日期，且收回筆數正確。 |
| 2 | 新增「只重新產生草稿」 | [MainForm.cs](../src/LineIntent/MainForm.cs) 第 293–303 行每次重試都先呼叫 JEV。將上次成功分析保留在記憶體，文字／模型／關係改動時失效；驗收相同輸入只新增 1 次 LLM 呼叫、不重算 JEV。可減少一次請求及相應成本，實際節省時間尚未用真實 API 測量。 |
| 3 | 降低 OCR 轉碼與大陣列配置 | [WindowsOcr.cs](../src/LineIntent/Capture/WindowsOcr.cs) 第 116–120 行使用 PNG 壓縮後再解碼；[LineBubbleDetector.cs](../src/LineIntent/Capture/LineBubbleDetector.cs) 第 19–50 行複製完整影像並建立陣列。先分段計時，再評估直接像素傳遞或只為氣泡偵測建立縮小遮罩。驗收包含 96／144 DPI、座標旋轉、角色與讀取順序不退步，並測配置量下降。 |
| 4 | 把 UI smoke test 納入可控的 Windows CI | 現行 CI 有掃描、核心測試與建置，沒有實際執行 UI／OCR smoke test。增加可用桌面工作階段及 OCR 語言套件的測試環境，避免把建置成功當成功能驗證。不能直接假定一般 hosted runner 具備繁中 OCR。 |

匯入解析的本機中位時間目前不到 1 ms，暫不優先重寫 regex 或加入平行處理；先處理資料正確性與有實際成本的流程。

## 已完成的 UI 修改與驗證

預設改成 `DropDownList`：姓名文字區與右側箭頭都可以展開，左側姓名標籤也會開啟對應清單。需要修正候選時勾選「手動輸入姓名」；關閉手動模式後會保留自訂姓名。

本機測試向兩個姓名欄位的文字區送出滑鼠點擊，確認原生 `DropDown` 事件發生；也測試標籤點擊、手動模式切換、自訂值保留及原本匯入流程。這不是只檢查控制項屬性。
