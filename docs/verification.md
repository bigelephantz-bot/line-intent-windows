### 同機合成效能比較

Release、同一組合成圖片、各暖身一次後測量五次。以下只量測氣泡偵測，不含模型請求或整體 OCR。

| 圖片 | 變更前中位時間 | 變更後中位時間 | 變更前託管配置／次 | 變更後託管配置／次 |
| --- | ---: | ---: | ---: | ---: |
| 1920×1080 | 21.15 ms | 7.58 ms | 26.22 MiB | 0.02 MiB |
| 3840×2160 | 60.85 ms | 14.39 ms | 64.18 MiB | 0.02 MiB |

原始報告位於忽略目錄 `artifacts/v0.7.0-before-memory.json`、`artifacts/v0.7.0-after-memory.json`。數字是暖身後的託管配置量，不是峰值記憶體；緩衝池會保留可重用陣列，原生 GDI／GPU／SoftwareBitmap 記憶體未包含在該數字中。首次租用陣列仍有配置。

改動包括移除完整託管像素副本、清空後歸還的遮罩／佇列緩衝池，以及移除每個像素掃描迴圈中隱含的閉包配置。擷取與 OCR 的 Bitmap／SoftwareBitmap 轉換改用受範圍檢查的逐列像素複製，不再以 PNG 壓縮／解碼作為中介。API 參考：[Microsoft SoftwareBitmap 記憶體存取](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/imaging)。

UI 錯誤根因是混合檢查多個待處理項目卻只回報同一則彈窗：修改某列角色並不能填滿該列文字；略過一列後，其他未知列仍可能阻止套用。新版獨立驗證每列並顯示列號，將「略過」與說話者分開，避免誤以為剛修改的列沒有生效。

單字重試只在既有辨識留白的小氣泡執行，使用原色與二值化兩種字形，加入本機定位文字協助行偵測，並要求定位文字位於預期區域，再以座標隔離真正字形。不同結果互相矛盾時不選猜測答案。所有處理在本機記憶體完成，不呼叫模型。

本機測試結果：`artifacts/v0.6.0-smoke/results.txt`。發布位置：`dist/LineIntent-win-x64-0.6.0/LineIntent.exe`。既有 API 設定與舊版發布資料夾保留；先前審查列出的兩項匯入 P2 不在此輪修改範圍。

## 首次現場確認

1. 在工具的「API 與設定」儲存一個服務的 Key，按「載入範例」→「分析對方意圖」，確認能取得七項結果。
2. 開啟 LINE 桌面對話，重新整理、擷取並框選訊息，確認 OCR 只包含所選區域。
3. 校正錯字與 `我：`／`對方：` 標記，再對自己的可見對話觸發分析。

若無法擷取，保留錯誤提示內容即可排查；不要將私密對話、API Key 或完整螢幕畫面貼到問題回報中。
